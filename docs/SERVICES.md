# Описание сервисов (Микросервисная архитектура)

Для обеспечения масштабируемости и независимости компонентов мы переходим на **микросервисную архитектуру**. Каждый сервис имеет свою зону ответственности и может быть развернут отдельно.

## 1. Bot Gateway Service (Шлюз Бота)
- **Ответственность**: Единственная точка входа для Telegram API.
- **Функции**:
    - Прием апдейтов через Webhooks.
    - Управление состояниями пользователей (FSM в Redis).
    - Маршрутизация запросов к соответствующим микросервисам через Message Broker.
- **Технологии**: `aiogram`, `Redis`, `NATS/RabbitMQ`.

## 2. Profile Service (Сервис профилей)
- **Ответственность**: Жизненный цикл пользователя и его анкеты.
- **Функции**:
    - Регистрация и валидация данных.
    - CRUD операции с профилями.
    - Управление медиа-контентом (связка с S3).
- **Технологии**: `FastAPI`, `PostgreSQL`, `SQLAlchemy`.

## 3. Matching Service (Сервис мэтчинга)
- **Ответственность**: Алгоритмы поиска и рекомендации.
- **Функции**:
    - Гео-поиск (PostGIS).
    - Фильтрация по интересам, возрасту и предпочтениям.
    - Выдача списка потенциальных кандидатов.
- **Технологии**: `FastAPI`, `PostGIS`, `Redis` (кэширование выборок).

## 4. Interaction Service (Сервис взаимодействий)
- **Ответственность**: Лайки, дизлайки и логика мэтчей.
- **Функции**:
    - Регистрация оценок.
    - Проверка взаимности (Match Detection).
    - Хранение истории взаимодействий.
- **Технологии**: `FastAPI`, `PostgreSQL`.

## 5. Notification Service (Сервис уведомлений)
- **Ответственность**: Асинхронная доставка событий пользователю.
- **Функции**:
    - Отправка уведомлений о новых мэтчах.
    - Системные рассылки.
- **Технологии**: `Python`, `gRPC/NATS`.

## 6. Message Broker (Шина событий)
- **Ответственность**: Связующее звено между сервисами.
- **Функции**: Асинхронный обмен сообщениями (Pub/Sub).
- **Технологии**: `NATS JetStream` или `RabbitMQ`.
